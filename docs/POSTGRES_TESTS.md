# Disposable permission-registry PostgreSQL17 acceptance

`npm run test:postgres` requires CONSENT_TEST_DISPOSABLE_POSTGRES=1 and CONSENT_TEST_ADMIN_URL pointing to an EMPTY loopback consent_ci database as migration user postgres, without query/fragment options. Remote/other/missing/unapproved targets are refused before connection, existing ledgers are refused, and no database is reset. The SDK's canonical migration runs unchanged except outer BEGIN/COMMIT wrappers owned by its transaction. Runtime sessions authenticate as a distinct restricted LOGIN with NOINHERIT/NOSUPERUSER/NOBYPASSRLS and use the actual pinned PostgreSQL driver. Fixed disposable fixture passwords are not production credentials.

Five authored TCP-session groups cover acceptance versus decline/cancellation, evaluation waiting behind a real withdrawal COMMIT, lost acceptance acknowledgement/fresh pool/current withdrawal and role/scope isolation. Distinct backend PIDs and session_user are asserted. A lock test observes pg_stat_activity wait_event_type=Lock and pg_blocking_pids, rather than inferring contention from timing. The withdrawal uses the actual registry domain API; its real SQL commit is gated by the test driver so evaluation is forced to wait.

The current checkpoint has no runtime change. Source review suggests evaluate reads current permission rows BEFORE the project lock acquired by its final audit, which may allow a stale approval after waiting on withdrawal. The test expects denial after that committed withdrawal. This is an UNREPRODUCED lead until actual CI proves the regression. Local typecheck/ordinary fixture-admission tests do not establish network execution. The host has no PostgreSQL/Docker and no local network qualification is claimed.

This draft still requires actual network execution, analysis/fix of any reproduced failure, source review and ALL required final-head jobs before merge. Production rights/identity proofing, static host mapping refresh, TLS/failover/throughput/multi-node/deployment and atomic downstream permission fencing remain unqualified. No live participant/permission evidence, sending/publication, payment or paid infrastructure is used.
