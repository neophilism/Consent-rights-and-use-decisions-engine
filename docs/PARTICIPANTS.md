# Participant consent offers (implementation checkpoint)

`PermissionRegistry.createOffer` stores a manager-authored disclosure and exact permission terms as a proposal, not consent. A trusted host binds authenticated human identities to subjects through the registry policy. `reviewOffer` returns only an offer belonging to that participant and its current consent, if any. It does not enumerate resources or other participants.

`respondToOffer` requires the viewed offer revision and digest. Acceptance additionally requires `acknowledged: true`; decline does not require an affirmative acknowledgement. The registry atomically stores a deterministic consent, resolved offer, audit assertion and impact event. Retry the same command ID and exact input after uncertain acknowledgement; do not invent a new ID. Expired, cancelled, already resolved or stale offers cannot create another consent. `cancelOffer` cancels only unanswered proposals and never withdraws accepted consent. The existing participant-scoped `withdraw` method withdraws current consent.

The digest binds the exact disclosure and terms, not actual reading, comprehension, legal capacity or freedom from coercion. A manager may still record supplied consent evidence through the older evidence-recording API; that is a separate authority and must not be presented as participant self-capture. No proposal or consent grants copyright or release authorization.

This checkpoint has four new restricted-role PGlite integration test groups. Additional adversarial/recovery tests and final source review are pending. No participant HTTP endpoint, invitation delivery, login, identity verification, browser UI, live database contention or live acceptance is provided. Do not expose the Database, registry manager methods or deployment identity mappings directly to a participant. The host must authenticate each request, supply current time and context, implement session/CSRF controls and present exact terms accessibly without presupposed acceptance. No real participants or communications were used.
